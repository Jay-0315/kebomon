## 3. ビジネスロジック詳細

### 3.1 出席チェックロジック

```
1. last_attendance_date が今日の日付と一致 → エラー（既にチェック済み）
2. streak_days 計算
   - last_attendance_date が昨日 → streak_days + 1
   - それ以外 → streak_days = 1
3. ポイント付与: [50, 100, 150] のランダム1択
4. attendance_days + 1、month_days + 1
5. 週次報酬チェック: month_days が 7 の倍数ごとに卵付与
   - 1〜2週目（7日・14日）: big_eggs + 1
   - 3〜4週目（21日・28日）: golden_eggs + 1
6. last_attendance_date を今日の日付に更新
```

### 3.2 ガチャロジック

```
レアリティ確率:
  common:   60%
  rare:     25%
  epic:     10%
  legendary: 4%
  mythic:    1%

ピティシステム（gacha_pity_count）:
  - 10回以内に rare+ が出なければ次回 rare 以上確定
  - 80回以内に legendary+ が出なければ次回 legendary 以上確定

重複処理:
  - 既に所有のケボモン → ポイントに変換（レアリティ別変換量）
  - 未所有 → user_characters にレコード作成
```

### 3.3 ケボモン強化ロジック

```
強化レベル上限: キャラクターごとに定義
必要強化石: レベルに応じて増加
成功確率: レベルに応じて減少
失敗時: 強化石のみ消費、レベル変化なし
最大強化達成: それ以上の強化不可
```

### 3.4 コロシアムティアシステム

```
ティア区分（tierPoints 基準）:
  Bronze    :    0〜999
  Silver    : 1000〜1999
  Gold      : 2000〜2999
  Platinum  : 3000〜3999
  Diamond   : 4000〜7999
  Master    : 8000〜...
  Challenger: シーズン上位者（特別付与）

バトル結果:
  勝利 → +20〜30 pts（連勝ボーナスあり）
  敗北 → -15〜20 pts（0未満にはならない）
```

### 3.5 通知生成フロー

```
1. イベント発生（コメント作成・業績達成など）
2. NotificationsService.create() 呼び出し
3. 受信ユーザーの app_settings.language を DB から取得
4. language が "ja" かつ日本語テキストあり → 日本語で保存
   それ以外 → 韓国語で保存
5. notifications テーブルにレコード作成
6. NotificationGateway.emitToUser() でリアルタイム配信
7. Web Push 通知を非同期送信（失敗しても主フロー不中断）
```

### 4.2 主要 Context

#### AppDataContext

```typescript
interface AppDataContextValue {
  hasInitialized: boolean;
  isLoading: boolean;
  profile: UserProfile;
  settings: AppSettings;
  posts: CommunityPost[];
  rewardSummary: RewardSummary;
  updateSettings: (s: Partial<AppSettings>) => Promise<void>;
  refreshData: () => Promise<void>;
```

```typescript
interface LangContextValue {
  lang: "ko" | "ja";
  t: (key: TranslationKey) => string;
}
```

- `AppDataContext.settings.language` を参照して言語を決定
- `translate(lang, key)` はフォールバックとして韓国語を返す

## 6. セキュリティ設計

### 6.1 認証フロー（JWT）

```
ログイン成功
  → サーバー: JWT 生成（sub: userId, exp: 30d）
  → クライアント: localStorage["kebo-auth-token"] に保存
  → 以降のリクエスト: Authorization: Bearer <token> ヘッダーに付与

トークン検証
  → JwtAuthGuard: JwtStrategy で署名検証
  → 無効・期限切れ → 401 → クライアントはログイン画面へ遷移
```

### 6.2 パスワードハッシュ

- bcryptjs: saltRounds = 10
- パスワード変更時には `password_change_history` を更新

### 6.3 メール認証コード

- 6桁数字コード
- 有効期限: 10分（設定値）
- 使用済みフラグ（`used_at`）で再利用防止
